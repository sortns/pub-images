# sortns/powerdns

[![Docker Hub](https://img.shields.io/docker/v/sortns/powerdns?sort=semver)](https://hub.docker.com/r/sortns/powerdns)
[![GitHub](https://img.shields.io/badge/source-GitHub-181717?logo=github)](https://github.com/sortns/pub-images/tree/master/images/powerdns)

A single container running both **PowerDNS Authoritative 4.9** (internal, port 5300) and
**PowerDNS Recursor 5.1** (user-facing, port 53) managed by supervisord.

```
clients → recursor :53  →  (internal zones) → auth :5300 (PostgreSQL backend)
                        →  (external/public) → upstream resolvers
```

Forward zones and NTAs are pulled automatically from the auth API every 5 minutes by
`pdns_sync_forward_zones`. RPZ is served directly from the auth server database via
`rpzPrimary()` — no local zone files needed.

On first boot, the image creates empty placeholder files for the generated recursor
forward-zone and NTA includes so the recursor can start before the first sync completes.

## Quick start

```bash
docker run -d \
  -e PDNS_API_KEY=changeme \
  -e PDNS_GPGSQL_HOST=pg.example.local \
  -e PDNS_GPGSQL_USER=pdns \
  -e PDNS_GPGSQL_PASSWORD=secret \
  -e PDNS_GPGSQL_DBNAME=pdns \
  -p 53:53/udp -p 53:53/tcp \
  -p 8081:8081 \
  sortns/powerdns:latest
```

The target PostgreSQL database must already contain the PowerDNS authoritative schema.
If tables like `domains` and `records` do not exist, `pdns_server` will exit with
`ERROR: relation "domains" does not exist`.
For reference: https://doc.powerdns.com/authoritative/backends/generic-postgresql.html#default-schema 

The PostgreSQL role from `PDNS_GPGSQL_USER` must also own the schema objects or have
permissions on them. If the schema was loaded by another role, `pdns_server` can fail with
`ERROR: permission denied for table domains`.
Example fix:

```sql
GRANT USAGE ON SCHEMA public TO pdns;
GRANT SELECT, INSERT, UPDATE, DELETE ON ALL TABLES IN SCHEMA public TO pdns;
GRANT USAGE, SELECT, UPDATE ON ALL SEQUENCES IN SCHEMA public TO pdns;
ALTER DEFAULT PRIVILEGES IN SCHEMA public
  GRANT SELECT, INSERT, UPDATE, DELETE ON TABLES TO pdns;
ALTER DEFAULT PRIVILEGES IN SCHEMA public
  GRANT USAGE, SELECT, UPDATE ON SEQUENCES TO pdns;
```

If you want `pdns` to fully own the imported schema instead of using grants, change the
owner of the imported tables and sequences to `pdns`.

## Ports

| Port | Protocol | Description |
|------|----------|-------------|
| 53   | UDP/TCP  | DNS — PowerDNS Recursor (user-facing) |
| 8081 | TCP      | Auth server HTTP API |
| 8082 | TCP      | Recursor HTTP API (disabled by default) |

Port **5300** (auth internal) is not exposed — it is only reachable by the recursor inside the container.

## Environment variables

### Auth server (pdns-server / PostgreSQL backend)

| Variable | Default | Description |
|----------|---------|-------------|
| `PDNS_API_KEY` | _(empty)_ | API key for the auth server HTTP API |
| `PDNS_LOCAL_PORT` | `5300` | Auth server listen port (internal) |
| `PDNS_LOCAL_ADDRESS` | `0.0.0.0` | Auth server bind address |
| `PDNS_GPGSQL_HOST` | `db` | PostgreSQL host |
| `PDNS_GPGSQL_PORT` | `5432` | PostgreSQL port |
| `PDNS_GPGSQL_USER` | `pdns` | PostgreSQL user |
| `PDNS_GPGSQL_PASSWORD` | `pdns` | PostgreSQL password |
| `PDNS_GPGSQL_DBNAME` | `pdns` | PostgreSQL database |
| `PDNS_GPGSQL_PREPARED_STATEMENTS` | `no` | Enable prepared statements |
| `PDNS_WEBSERVER_PORT` | `8081` | Auth API/webserver port |
| `PDNS_WEBSERVER_ALLOW_FROM` | `127.0.0.1` | Auth API access CIDR |
| `PDNS_ALLOW_AXFR_IPS` | `127.0.0.1` | AXFR allowed IPs |
| `PDNS_ALLOW_NOTIFY_FROM` | _(empty)_ | Notify allowed IPs |
| `PDNS_LOGLEVEL` | `4` | Log level |
| `PDNS_CACHE_TTL` | `60` | Cache TTL (s) |

### Recursor (pdns-recursor)

| Variable | Default | Description |
|----------|---------|-------------|
| `PDNS_RECURSOR_LOCAL_PORT` | `53` | Recursor listen port |
| `PDNS_RECURSOR_ALLOW_FROM` | `0.0.0.0/0` | Recursor query ACL |
| `PDNS_RECURSOR_UPSTREAM_RESOLVER_1` | `8.8.8.8` | Primary upstream resolver |
| `PDNS_RECURSOR_UPSTREAM_RESOLVER_2` | `77.88.8.8` | Secondary upstream resolver |
| `PDNS_RECURSOR_FORWARD_ZONES_FILE` | `/etc/powerdns/forward-zones.yml` | Generated by sync script |
| `PDNS_RECURSOR_MAX_CACHE_TTL` | `300` | Max cache TTL (s) |
| `PDNS_RECURSOR_MAX_NEGATIVE_TTL` | `60` | Max negative TTL (s) |
| `PDNS_RECURSOR_THREADS` | `2` | Recursor threads |
| `PDNS_RECURSOR_LOG_LEVEL` | `4` | Log level |
| `PDNS_RECURSOR_WEBSERVER_ENABLED` | `false` | Enable recursor API |
| `PDNS_RECURSOR_WEBSERVER_PORT` | `8082` | Recursor API port |
| `PDNS_RECURSOR_API_KEY` | _(empty)_ | Recursor API key |

### RPZ (database-backed, no local files)

| Variable | Default | Description |
|----------|---------|-------------|
| `PDNS_RECURSOR_RPZ_PRIMARY` | `127.0.0.1:5300` | Auth server serving RPZ zone |
| `PDNS_RECURSOR_RPZ_ZONE_NAME` | `rpz` | RPZ zone name |
| `PDNS_RECURSOR_RPZ_REFRESH` | `60` | RPZ refresh interval (s) |

### Zone sync (auth API → recursor forward-zones)

| Variable | Default | Description |
|----------|---------|-------------|
| `PDNS_SYNC_API_URL` | `http://127.0.0.1:8081/api/v1` | Auth server API URL |
| `PDNS_SYNC_SERVER_ID` | `localhost` | Auth server ID |
| `PDNS_SYNC_INTERVAL` | `300` | Sync interval (s) |
